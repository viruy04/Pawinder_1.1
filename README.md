# Pawinder

## 1. Название и команда

**Pawinder** — Android-приложение для подбора животных из приютов.

**Технологии:** Java, Android Studio, Spring Boot.

## 2. Пользователь

Основной пользователь — человек, который хочет взять животное из приюта и ищет подходящего питомца.

## 3. Проблема

Поиск животных через сайты приютов и социальные сети может быть неудобным: пользователю приходится самостоятельно просматривать множество публикаций, сравнивать животных и искать контактную информацию.

Это затрудняет поиск подходящего питомца и может снижать интерес пользователя к длительному поиску.

## 4. Текущий способ работы

Сейчас пользователь может просматривать сайты приютов, публикации в социальных сетях и фотографии животных, самостоятельно переходя между страницами и изучая информацию о каждом питомце.

В Pawinder планируется упростить этот процесс с помощью карточек животных и системы свайпов.

## 5. Ожидаемый результат

После реализации основных функций пользователь сможет:

* просматривать карточки животных из приютов;
* выбирать понравившихся животных с помощью свайпов;
* сохранять понравившихся питомцев в избранном;
* просматривать подробную информацию о выбранном животном;
* получать контактную информацию приюта;
* использовать персонализированный подбор животных после реализации алгоритма рекомендаций.

## 6. Собственная логика

Команда самостоятельно разрабатывает логику Android-приложения и серверную часть на Spring Boot.

Планируемая собственная логика включает:

1. **Обработка свайпов.** Определение направления свайпа и преобразование его в действие пользователя: «нравится» или «не нравится».
2. **Работа с избранным.** Добавление и удаление выбранных животных, сохранение списка и получение информации о сохранённых питомцах.
3. **Подбор животных.** В дальнейшем — анализ предпочтений пользователя на основе его действий и выбор подходящих животных.

Взаимодействие с внешним API организовано через Spring Boot. Команда использует готовый источник данных, самостоятельно разрабатывая логику обработки и отображения информации в приложении.

## 7. Модуль-кандидат

**Модуль обработки свайпов и пользовательских предпочтений.**

Модуль можно отдельно наблюдать и тестировать: он получает действие пользователя, определяет его тип и в дальнейшем передаёт результат для сохранения предпочтения.

После реализации можно будет проверять:

* сохраняется ли выбор;
* распознавание нажатия/жеста;
* исключается ли повторное добавление одного животного в избранное;
* как пользовательские предпочтения влияют на подбор животных.

## 8. Внешние ресурсы

Для разработки и работы Pawinder используются:

* **Android-устройство или эмулятор** — для запуска приложения;
* **Android Studio** — среда разработки Android-клиента;
* **Spring Boot** — серверная часть для взаимодействия с API;
* **внешнее API** — источник данных о животных;
* **GitHub** — хранение исходного кода и совместная разработка;
* **GitHub Actions** — автоматическая проверка сборки проекта;
* **Mysql** — разработанная база данных.

Разработка ведётся на компьютерах команды под управлением Windows 11. Для тестирования используется Android-устройство или эмулятор.

## 9. Ограничения

* Команда состоит из двух человек.
* Проект разрабатывается в рамках практической работы и семестрового проекта, поэтому сроки ограничены.
* Работа с карточками зависит от доступности серверной части и внешнего API.
* Для получения данных необходимо корректное подключение Android-клиента к Spring Boot.

## 10. Критерий достижения цели проекта

Основная цель будет достигнута, когда пользователь сможет просматривать животных, выбирать понравившихся питомцев с помощью свайпов, сохранять их в избранном и открывать подробную информацию с контактами приюта.
