# Исходное состояние и ранние ограничения безопасности — Pawinder

Связано с [requirements.md](requirements.md) (FR-01…FR-10, NFR-01…NFR-03).

## 1. Как проверяющий получит нужное состояние 

| Что | Как получить |
|---|---|
| База данных | Запрос на сервер с базой данных (база данных развернута на сервере (ссылка на сервис: https://tidbcloud.com/)). Со стороны проверяющего дополнительных действий не требуется. |
| Запуск backend (Spring Boot) и Android-клиента | Backend запускается на сервере (ссылка на сервис: https://dashboard.render.com/). Со стороны проверяющего дополнительных действий не требуется. |
| Учебные учётные записи | Два тестовых пользователя, созданные скриптом; пароли в репозитории не хранятся |
| Внешний API | Учебный режим: фиксированный набор карточек в тестовых данных, чтобы проверка не зависела от личных ключей разработчиков и доступности API |

**Набор тестовых карточек** (покрывает критерии из `requirements.md`):

- карточка с фото, кличкой, возрастом и контактами приюта (FR-02, FR-07), по образцу из `examination.md`: собака Рекс, 2 года;
- карточка без фото (FR-10б);
- карточка без контактов приюта (FR-07);
- сценарий пустой ленты — пользователь, у которого все карточки уже просмотрены (FR-10а);
- сценарий недоступного источника — остановленный backend или отключённая сеть (FR-10в).

**Для будущих проверок:** тестовые данные для проверки отсутствия дублей в избранном (FR-03) и для замера отклика (NFR-01, нужное число карточек).

## 2. Ранние ограничения безопасности

| Вопрос | Ответ |
|---|---|
| Что важно сохранить или ограничить | Учётные данные и профиль пользователей, список избранного, ключи внешнего API, пароль к БД |
| Откуда приходит недоверенный ввод | Поля регистрации, входа и профиля; ответы внешнего API (тексты, ссылки на фото, отсутствующие или неожиданные поля) |
| Кто должен иметь доступ к существенным действиям | Избранное и профиль — только владелец аккаунта; БД — только backend |
| Реалистичный ущерб | Чужой доступ к аккаунту или избранному; утечка ключа или пароля БД через репозиторий; падение клиента из-за некорректного ответа источника |
| Где хранится конфигурация с секретами и что нельзя выводить в журнал | Переменные окружения и GitHub Secrets, не в Git; в журналы и сообщения об ошибках не выводить пароли, токены, ключи API |


## 3. Планируемая проверка

| Требование | Когда и как проверим |
|---|---|
| NFR-02 | Поиск секретов в репозитории при каждом PR (review) и перед сдачей |
| NFR-03 | После реализации авторизации: запрос чужого избранного и профиля должен вернуть отказ |
| FR-10 | Прогон трёх сценариев ошибок на эмуляторе после реализации |
