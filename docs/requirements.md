# Спецификация требований 1.0 — Pawinder

## 1. Основной сценарий в границах MVP

Вход → лента карточек → свайп вправо (в избранное) или влево (пропуск) → избранное → подробная информация → контакты приюта.

Существенные ошибочные исходы: неверные данные входа; недоступен backend или внешний API; пустая лента; у животного нет фото или контактов.


## 2. Функциональные требования

| ID | Требование | Основание | Приоритет | Критерий приёмки и способ проверки |
|---|---|---|---|---|
| FR-01 | Регистрация и вход | MVP-01 | MVP | **Дано:** логин не занят. **Когда:** регистрация с корректными данными. **Тогда:** аккаунт создан, вход возможен. **Ошибки:** занятый логин или неверный пароль → понятное сообщение, сессия не создаётся. Проверка: ручной прогон + запись в БД |
| FR-02 | Лента карточек | MVP-02, examination | MVP | **Дано:** источник данных доступен. **Когда:** открыта лента. **Тогда:** карточка содержит фото, кличку, возраст и краткое описание (если источник их отдаёт). Проверка: эмулятор + тестовые карточки |
| FR-03 | Свайп вправо добавляет в избранное; одно животное не дублируется в избранном одного пользователя | MVP-03, development-process §8 | MVP | **Дано:** карточка уже в избранном. **Когда:** повторный свайп вправо. **Тогда:** второй записи нет. Проверка: запрос к таблице избранного после действия |
| FR-04 | Свайп влево пропускает животное и не добавляет в избранное | MVP-04 | MVP | **Дано:** карточка в ленте. **Когда:** свайп влево. **Тогда:** в избранном записи нет. Показ пропущенного повторно не определён (OQ-02) |
| FR-05 | Избранное: просмотр отмеченных животных | MVP-05 | MVP | **Дано:** отмечено 2 животных. **Когда:** открыта вкладка «Избранное». **Тогда:** оба в списке. Сохранение после перезапуска приложения (OQ-03): предлагаем «да» |
| FR-06 | Подробная информация о животном из избранного | MVP-06 | MVP | **Когда:** открыта карточка из избранного. **Тогда:** показаны данные животного. Проверка: ручная |
| FR-07 | Контакты приюта на экране животного | MVP-07 | MVP | **Дано:** источник передал контакты. **Тогда:** они отображены. **Дано:** контактов нет. **Тогда:** сообщение «контакты не указаны», без падения |
| FR-08 | Личный кабинет: просмотр и изменение полей профиля | MVP-08 | MVP | **Когда:** изменено допустимое поле и сохранено. **Тогда:** после повторного входа значение сохранилось. Список полей: Имя, Фамилия, Дата рождения, Почта, Страна, Город, Никнейм, Выбор аватарки |
| FR-09 | Навигация через нижнее меню | MVP-09 | MVP | Каждая вкладка открывается и возвращает к своему экрану. Проверка: ручная |
| FR-10 | Обработка ошибок: пустой список, нет изображения, недоступен источник данных | MVP-10 | MVP | **Дано:** (а) пустая лента, (б) карточка без фото, (в) backend/API недоступен. **Тогда:** (а) сообщение, (б) заглушка вместо фото, (в) сообщение об ошибке; во всех случаях приложение не закрывается |

## 3. Нефункциональные требования

Числа — **цели**, а не доказанные характеристики.

| ID | Требование | Основание | Приоритет | Критерий и способ проверки |
|---|---|---|---|---|
| NFR-01 | Отклик при загрузке следующей карточки | Удобство свайпов | MVP | Среда: эмулятор + тестовый backend, не менее 50 карточек в БД. Измерение: 20 запросов следующей карточки. Цель: 95-й процентиль не более **2 с** (согласовать) |
| NFR-02 | Секреты (ключи API, пароли БД) не попадают в репозиторий, журналы и сообщения об ошибках | DoD, development-process §6 | MVP | Поиск по репозиторию (`git grep`), review PR; секреты — только в переменных окружения / GitHub Secrets |
| NFR-03 | Избранное и профиль доступны только их владельцу; пароль хранится не в открытом виде | Ранние ограничения безопасности ([test-data-and-security.md](test-data-and-security.md)) | MVP (**предлагается добавить в baseline**; если не успеваем — перенос в резерв через CR) | Запрос к избранному/профилю другого пользователя → отказ; в БД нет открытых паролей |

## 4. Собственная логика и модуль-кандидат

Описаны в [README.md](README.md) (разделы 6–7). Для MVP собственная логика — обработка свайпов и избранное без дублей (FR-03, FR-04, FR-05); анализ предпочтений относится к резерву. Объект эксперимента — модуль обработки свайпов: можно отдельно проверять сохранение выбора и отсутствие дублей.

## 5. Резерв

Не входит в baseline, перечень — в [mvp.md](mvp.md), раздел 3.

## 6. Ограничения и допущения

Ограничения — в [README.md](README.md), раздел 9, и [examination.md](examination.md).

**Допущения (не подтверждены):** карточки и свайпы упрощают просмотр; избранное помогает вернуться к понравившимся, возврат к предыдущей карточке поможет не потерять анкету понравившегося питомца из-за случайного свайпа; 

**Уже доступно / планируется:** Выбор аватарки у пользователя, свайпы карточек по жесту и по кнопке, лента с животными (аналог бесконечной ленты TikTok).
