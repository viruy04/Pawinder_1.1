# ADR-002. Заменяемость логики ленты Pawinder

**Автор:** Казакова А. Ю.  
**Статус:** принято

## 1. Контекст

В Android-клиенте Pawinder компонент `FeedAdapter` отображает карточки животных, а `FeedFragment` загружает данные и обрабатывает состояние ответа сервера. Обработка URL фотографий, проверка ответа и подготовка сообщения о сетевой ошибке вынесены в логику ленты.

При прямом использовании статических методов конкретного класса замена реализации требует изменения обращающихся к нему компонентов.

## 2. Рассмотренные варианты

**Вариант 1.** Оставить статические методы `FeedLogic`.

Преимущество — простота существующего кода. Недостаток — отсутствует общий контракт для взаимозаменяемых реализаций.

**Вариант 2.** Использовать общий интерфейс и единую точку выбора реализации.

Преимущество — потребители зависят от контракта, а не от конкретного класса. Недостаток — появляются дополнительные классы и необходимость проверять согласованность реализаций.

## 3. Решение

Использовать интерфейс `FeedLogicContract`, реализации `DefaultFeedLogic` и `AlternativeFeedLogic`, а также `FeedLogicProvider` для выбора текущей реализации.

Потребители получают объект через `FeedLogicProvider`. Переключение реализации выполняется в одном месте.

## 4. Последствия

Положительные:
- реализации имеют единый контракт;
- потребители не должны изменяться при переключении реализации;
- обе реализации можно проверять одинаковыми тестами.

Отрицательные:
- увеличивается количество классов;
- тесты должны проверять согласованность обеих реализаций;
- статический класс `FeedLogic` временно сохраняется для совместимости с существующими тестами.

## 5. Стоимость и проверка

Стоимость решения — введение интерфейса, двух реализаций и точки выбора, а также поддержка тестов и документации.

Критерии проверки:
1. сборка приложения проходит при выборе каждой реализации;
2. тесты обеих реализаций проходят;
3. код `FeedAdapter` и `FeedFragment` не меняется при переключении реализации;
4. карта модулей соответствует фактическим зависимостям.

Результаты проверки фиксируются в отчёте по практической работе.
