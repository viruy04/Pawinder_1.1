# Карта модулей проекта Pawinder

**Проект:** Pawinder  
**Автор:** Казакова А. Ю.

## 1. Назначение

Карта описывает основные модули Android-клиента, их ответственность и зависимости. Она используется для определения границ изменений и выбора модулей, которые можно отдельно тестировать или заменять.

## 2. Состав модулей

| Модуль | Основные компоненты | Ответственность | Статус |
|---|---|---|---|
| Интерфейс ленты | `FeedFragment` | Отображение ленты, запрос данных, обработка состояния загрузки и ошибок | Реализован |
| Адаптер ленты | `FeedAdapter` | Привязка данных животного к карточке и загрузка изображения | Реализован |
| Логика ленты | `FeedLogic`, `FeedLogicContract` | Формирование URL фотографии, проверка ответа, подготовка сообщения об ошибке | Реализован |
| Реализация логики по умолчанию | `DefaultFeedLogic` | Реализация контракта логики ленты | Реализован |
| Альтернативная реализация | `AlternativeFeedLogic` | Вторая реализация того же контракта для проверки взаимозаменяемости | Реализован |
| Выбор реализации | `FeedLogicProvider` | Предоставление реализации потребителям ленты | Реализован |
| Модель животного | `Pet` | Представление данных животного | Реализован |
| Клиент API | `ApiClient` | Подготовка взаимодействия мобильного клиента с серверным API | Реализован |
| Тесты логики ленты | `FeedLogicTest`, `FeedLogicImplementationsTest` | Проверка обработки URL, ответов и сетевых ошибок | Реализованы |

## 3. Основные зависимости

1. `FeedFragment` использует `ApiClient` для загрузки списка животных.
2. `FeedFragment` использует `FeedLogicProvider` для проверки ответа и формирования сообщения об ошибке.
3. `FeedAdapter` использует `FeedLogicProvider` для обработки URL фотографии.
4. `FeedAdapter` отображает данные модели `Pet` с помощью представлений карточки и библиотеки Glide.
5. `DefaultFeedLogic` и `AlternativeFeedLogic` реализуют общий контракт `FeedLogicContract`.
6. `FeedLogicTest` проверяет существующий класс `FeedLogic`, а `FeedLogicImplementationsTest` проверяет обе реализации контракта.

## 4. Граница заменяемости

Потребители `FeedAdapter` и `FeedFragment` получают реализацию через `FeedLogicProvider`. Выбор между `DefaultFeedLogic` и `AlternativeFeedLogic` выполняется в одном месте. Для переключения реализации не требуется изменять код потребителей.

## 5. Проверка актуальности

Карта сверяется с исходным кодом после изменения состава модулей, зависимостей или точки выбора реализации. Статус тестов подтверждается запуском Gradle, а не наличием тестовых файлов.
