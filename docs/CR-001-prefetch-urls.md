# CR-001: Асинхронная предзагрузка URL-адресов карточек

**Автор:** Казакова А. Ю.  
**Дата:** 17.11.2026  
**Отметка преподавателя:** признан допустимым, 17.11.2026

## Описание изменения

Модуль логики ленты (`logic/feed`) должен предварительно определять URL фотографий следующих 3 карточек животных в фоновых потоках, чтобы ускорить их отображение при прокрутке ленты.

Для этого добавляется класс `FeedPrefetcher`. Он владеет пулом потоков (`ExecutorService`) и кэшем URL. `FeedFragment` создаёт `FeedPrefetcher` и закрывает его при уничтожении экрана. `FeedAdapter` только читает кэш.

## Обоснование

Сейчас URL фотографии определяется только в момент показа карточки в `FeedAdapter`. При быстрой прокрутке это может вызывать задержки. Предзагрузка подготовит данные заранее.

Пул не размещается в `FeedLogic` или `DefaultFeedLogic`. `FeedLogic` — статический класс, а `DefaultFeedLogic` — синглтон в `FeedLogicProvider`, живущий до конца процесса. Его нельзя остановить при закрытии экрана. Поэтому владельцем пула является объект с жизненным циклом экрана (см. ADR-002 и `docs/module-map.md`).

## Требования к реализации

1. `FeedPrefetcher` создаёт `ExecutorService` с фиксированным пулом из 2 потоков.
2. Метод `prefetchUrls(List<Pet> pets, int startIndex)` запускает фоновые задачи для следующих 3 карточек, начиная с `startIndex + 1`. Выход за границы списка безопасно обрезается.
3. Каждая задача вызывает `FeedLogicProvider.getInstance().resolvePhotoUrl(...)` и сохраняет результат в кэш `ConcurrentHashMap<Integer, String>`. Ключ — `pet.getId()`.
4. Значение `null` в кэш не записывается: отсутствие записи означает, что URL не предрассчитан, и `FeedAdapter` определяет его сам, как и раньше.
5. Метод `getCachedUrl(int petId)` возвращает значение из кэша или `null`. Базовый URL сервера выносится в общую константу, которой пользуются и `FeedAdapter`, и `FeedPrefetcher`.
6. `resolvePhotoUrl` не блокируется, поэтому `InterruptedException` в задаче не возникает. Перед работой и перед записью в кэш задача проверяет `Thread.currentThread().isInterrupted()`. Если поток прерван, задача завершается, не записывая результат. Флаг прерывания не сбрасывается.
7. `FeedPrefetcher` реализует `AutoCloseable`. Метод `close()` вызывает `shutdownNow()` и очищает кэш. `FeedFragment` вызывает его в `onDestroyView()`.
8. Повторный вызов `close()` безопасен. После `close()` вызов `prefetchUrls` ничего не запускает.

## Поведение при отказах

| Случай | Поведение |
|---|---|
| Ошибка получения ресурса: пул не принял задачу (`RejectedExecutionException`) или поток не создан (`OutOfMemoryError`) | Задача не запускается, ошибка логируется, кэш не изменяется, лента работает без предзагрузки |
| Ошибка во время работы: `resolvePhotoUrl` выбросил исключение | Задача перехватывает исключение, URL в кэш не записывается, ошибка логируется, поток возвращается в пул и продолжает работу |
| Таймаут | Не применяется: операция локальная, без обращения к сети, исход однозначен. Повтор не применяется по той же причине |
| Ранний выход: `Future.cancel(true)` или `close()` | Поток прерывается, задача завершается без записи в кэш, пул останавливается |
| Деградация | При отсутствии записи в кэше `FeedAdapter` определяет URL сам. Пользователь видит ту же ленту, но без ускорения |

## Влияние на системные границы

| Свойство | До CR-001 | После CR-001 |
|---|---|---|
| Граница модуля | `FeedAdapter` вызывает `resolvePhotoUrl` в момент показа карточки | `FeedFragment` вызывает `prefetchUrls`, `FeedAdapter` читает `getCachedUrl`; `resolvePhotoUrl` вызывается также из фоновых потоков |
| Владелец ресурса | Ресурса нет | Пул потоков принадлежит `FeedPrefetcher`, объект принадлежит `FeedFragment` |
| Передача владения | Нет | Владение не передаётся. `FeedAdapter` заимствует кэш и не закрывает пул |
| Требования к освобождению | Нет | `close()` вызывается в `onDestroyView()` на любом пути закрытия экрана; пул останавливается через `shutdownNow()` |
| Поведение при частичном отказе | Нет | Отказ пула или задачи не ломает ленту: используется прежний путь определения URL в адаптере |
