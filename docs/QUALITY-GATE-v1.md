# Quality Gate v1

## 1. Назначение

Quality Gate — набор автоматических проверок, которые должны пройти перед объединением программного изменения. Проверки помогают обнаруживать ошибки, проблемы качества кода и случайное попадание секретов в репозиторий.

## 2. Критерии прохождения

| Критерий | Условие прохождения | Действие при нарушении | Ответственный |
|---|---|---|---|
| Модульные тесты | Команда `./gradlew testDebugUnitTest` завершается успешно | Остановить CI, исправить код или тесты | Автор изменения |
| Android Lint | Команда `./gradlew lintDebug` завершается успешно | Изучить отчёт, исправить ошибки анализа | Автор изменения |
| Проверка DefaultLocale | В отчёте Lint отсутствуют замечания `DefaultLocale` | Остановить CI и исправить использование локали | Автор изменения |
| Сборка приложения | Команда `./gradlew assembleDebug` завершается успешно | Исправить ошибки сборки | Автор изменения |
| Проверка секретов | Проверка Gitleaks завершается успешно | Удалить секрет из кода и при необходимости заменить его | Автор изменения |
| Code Review | Изменения просмотрены другим участником; критические замечания устранены | Доработать изменение и запросить повторную проверку | Автор и проверяющий |

## 3. Быстрый и расширенный контуры CI

**Быстрый контур** включает модульные тесты, Android Lint и проверку `DefaultLocale`. Он предназначен для раннего обнаружения проблем при разработке.

**Расширенный контур** дополнительно включает сборку APK, проверку секретов и проверки, связанные с выпуском версии. Проверки выпуска выполняются при соответствующих событиях CI, например при создании тега релиза.

В текущей конфигурации GitHub Actions тесты, Lint, сборка и проверка секретов могут запускаться отдельными заданиями параллельно. Поэтому деление на быстрый и расширенный контуры является логическим описанием набора проверок, а не утверждением, что все задания уже реализованы как две отдельные последовательные стадии.

## 4. Условия блокировки

Изменение не считается прошедшим Quality Gate, если:
- не проходят модульные тесты;
- не проходит Android Lint;
- обнаружены замечания `DefaultLocale`;
- приложение не собирается;
- проверка секретов завершается ошибкой.

Предупреждения Android Lint по другим правилам не блокируют текущую версию Quality Gate автоматически. Их необходимо изучать и планировать исправления с учётом риска.

## 5. Риски и ограничения

- Не все предупреждения Lint означают реальную ошибку.
- Отсутствие замечаний `DefaultLocale` не гарантирует полного отсутствия дефектов.
- Успешная сборка не заменяет функциональное тестирование.
- Проверка секретов может требовать анализа найденных совпадений, чтобы отличить настоящие секреты от тестовых данных.
- Результат Code Review зависит от внимательности проверяющего.

## 6. Развитие Quality Gate

В дальнейшем можно расширить набор автоматических проверок: добавить дополнительные правила Lint, увеличить покрытие тестами, настроить обязательное одобрение Pull Request и проверку качества зависимостей.
