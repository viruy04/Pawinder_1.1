# MVP Pawinder 0.1

## 1. Цель MVP

Проверить основной пользовательский сценарий: пользователь входит в приложение, просматривает карточки животных, вручную выбирает понравившихся питомцев, открывает избранное и изучает подробную информацию о животном и приюте.

## 2. Обязательные функции

| ID | Функция | Критерий готовности |
|---|---|---|
| MVP-01 | Регистрация и вход | Пользователь может создать аккаунт и войти; ошибки обрабатываются |
| MVP-02 | Лента животных | Отображаются карточки с фотографиями и основной информацией |
| MVP-03 | Свайп вправо | Животное добавляется в избранное |
| MVP-04 | Свайп влево | Животное пропускается и не добавляется в избранное этим действием |
| MVP-05 | Избранное | Можно просмотреть ранее отмеченных животных |
| MVP-06 | Подробная информация | Из избранного можно открыть данные о питомце |
| MVP-07 | Контакты приюта | На экране питомца доступны контактные данные, если они предоставлены источником |
| MVP-08 | Личный кабинет | Пользователь может просматривать и изменять предусмотренные поля профиля |
| MVP-09 | Навигация | Основные вкладки переключаются через нижнее меню |
| MVP-10 | Обработка ошибок | Пустые списки, отсутствующие изображения и ошибки источника данных не приводят к аварийному завершению |

## 3. Резерв функций

Следующие функции не блокируют приёмку MVP:

- алгоритм умного подбора на основе предпочтений и истории свайпов;
- отдельный режим думскроллинга для просмотра фотографий без отбора;
- расширенные фильтры по возрасту, размеру, породе и другим параметрам;
- дополнительные фотографии и расширенные сведения о питомцах, если они не предоставляются источником;
- синхронизация избранного между устройствами;
- кроссплатформенная версия с использованием Electron или других технологий.

## 4. Минимальный результат первой практической

Для первой демонстрации приоритетны переключение основных вкладок через нижнее меню, минимальный интерфейс, карточки животных и базовые свайпы.

## 5. Условия выхода из MVP

MVP считается готовым, когда выполнены критерии MVP-01–MVP-10, приложение проходит сборку и предусмотренные проверки, а известные ограничения зафиксированы в документации.

Функции резерва не должны задерживать завершение обязательного сценария.
