# Инструментальный контур проекта Pawinder

## 1. Назначение

Документ описывает инструменты сборки, тестирования и диагностики Android-клиента Pawinder.

Связанное архитектурное решение: ADR-001.md
## 2. Инструменты и их назначение

| Позиция | Средство | Назначение и способ подключения | Статус |
|---|---|---|---|
| Сборка | Gradle Wrapper 9.6.0, Android Gradle Plugin 9.4.1, Android SDK | Сборка Android-приложения через Gradle Wrapper | Требует проверки сборкой |
| Управление зависимостями | Gradle, `gradle/libs.versions.toml`, блок `dependencies` в `app/build.gradle.kts` | Объявление библиотек и версий, разрешение зависимостей при сборке | Конфигурация присутствует |
| Тестирование | JUnit 4.13.2, AndroidX Test JUnit 1.3.0, Espresso Core 3.7.0 | Модульные и инструментальные тесты | Требует проверки запуском тестов |
| Статический анализ | Android Lint, инспекции Android Studio | Поиск потенциальных ошибок без запуска приложения | Требует проверки |
| Динамическая диагностика | Android Studio Debugger, Logcat | Отладка запущенного приложения и просмотр журналов | Доступно в Android Studio; требует проверки на приложении |
| Профилирование | Android Studio Profiler | Анализ использования памяти и ресурсов во время выполнения | Запланировано для проверки |
| Непрерывная интеграция | GitHub Actions | Автоматическая проверка проекта при запуске workflow | Требует проверки актуального результата CI |

## 3. Параметры сборки

- Android Gradle Plugin: `9.4.1`.
- Gradle Wrapper: `9.6.0`.
- Критерий Gradle JVM: `25`.
- Java source/target compatibility: `11`.
- `compileSdk`: `37`.
- `targetSdk`: `37`.
- `minSdk`: `24`.
- `versionCode`: `1`.
- `versionName`: `1.0`.
- `BuildConfig` включён в настройках Android-сборки.

## 4. Маршрут воспроизведения

1. Получить исходный код проекта из репозитория.
2. Открыть проект в Android Studio.
3. Дождаться синхронизации Gradle и разрешения зависимостей.
4. Убедиться, что установлены необходимые JDK и Android SDK.
5. Выполнить сборку через Gradle Wrapper.
6. Установить приложение на эмулятор или Android-устройство.
7. Запустить приложение и проверить стартовый экран.
8. Открыть Logcat и проверить сообщения запуска.
9. Запустить доступные автоматические тесты.
10. Проверить результат выполнения CI в GitHub Actions.

## 5. Ограничения и подтверждение статусов

Наличие инструмента в конфигурации не подтверждает успешное выполнение проверки. Статусы сборки, тестирования и CI уточняются по фактическим результатам запусков. Инструменты, которые ещё не проверены, не считаются успешно настроенными.
