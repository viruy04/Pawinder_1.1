# Инструментальный контур проекта Pawinder

## 1. Назначение

Документ описывает инструменты, используемые для сборки, проверки и диагностики Android-клиента Pawinder на Java.

Связанное техническое решение: ADR-001.md

## 2. Инструменты и их назначение

| Позиция | Средство | Назначение и способ подключения | Статус |
|---|---|---|---|
| Сборка и подготовка к исполнению | Gradle Wrapper, Android Gradle Plugin, Android SDK | Сборка Android-приложения из исходного кода с помощью Gradle Wrapper | Проверить локальную сборку |
| Управление зависимостями | Gradle, файлы конфигурации проекта | Объявление библиотек и версий в конфигурационных файлах Gradle | Проверить фактические зависимости |
| Тестирование | Gradle, JUnit (если настроен в проекте) | Запуск автоматических тестов средствами Gradle | Проверить наличие и запуск тестов |
| Статический анализ | Android Lint, Android Studio Inspections | Поиск потенциальных ошибок и проблем в исходном коде без запуска приложения | Запланировано: проверить запуск анализа |
| Динамическая диагностика | Android Studio Debugger, Logcat | Отладка работающего приложения и просмотр диагностических сообщений | Доступно в среде разработки; проверить на компоненте |
| Профилирование | Android Studio Profiler | Исследование потребления памяти и ресурсов работающим приложением | Запланировано: выполнить базовую проверку |
| Автоматические проверки (CI) | GitHub Actions | Автоматический запуск проверок при событиях в репозитории согласно настройкам workflow | Настроено ранее; проверить успешный запуск актуальной версии |

## 3. Маршрут подготовки к исполнению

1. Получить исходный код проекта из репозитория.
2. Открыть проект в Android Studio и дождаться синхронизации Gradle.
3. Убедиться, что необходимые версии JDK, Android SDK и зависимости доступны.
4. Собрать приложение с помощью Gradle Wrapper.
5. Установить собранное приложение на Android-устройство или эмулятор.
6. Запустить приложение и проверить начальный экран.
7. Просмотреть диагностические сообщения в Logcat.
8. Выполнить доступные автоматические проверки и проверить результат CI.

## 4. Ограничения

Фактический статус каждого инструмента подтверждается запуском соответствующей команды или проверкой в среде разработки. Инструменты, которые ещё не проверены или не настроены, не считаются успешно работающими только на основании наличия в документации.
