# ADR-003: Выбор модели исполнения для FeedLogic

- Статус: принято
- Контекст: практическая работа № 4
- Дата: 2026-11-19

## Контекст

В рамках практической работы исследованы последовательное и параллельное
вычисления, конкурентный ввод-вывод и защита общего изменяемого состояния.
Дополнительно проведено сравнение DefaultFeedLogic и AlternativeFeedLogic
в проекте Pawinder.

## Результаты экспериментов

1. CPU-bound: на 12 логических процессорах ускорение параллельного вычисления
   составило 6,813 раза относительно последовательной реализации.
   Эффективность при этом составила 56,8 %, поэтому ускорение не является
   линейным.

2. I/O-bound: наилучший результат получен при конкурентности 4:
   4,149 мс и 7712,52 МиБ/с. При конкурентности 12 результат оказался
   немного хуже. Измерения проводились с прогретым файловым кэшем ОС.

3. Общее состояние: несинхронизированное увеличение счётчика нарушило
   инвариант в 2 из 10 запусков. После добавления synchronized инвариант
   выполнялся во всех 10 проверках.

4. FeedLogic: обе реализации прошли функциональные проверки, а результаты
   их работы совпали. В первом измерении альтернативная реализация работала
   в 1,254 раза дольше базовой, во втором — в 1,036 раза дольше.
   Разница между измерениями показывает влияние шума и условий запуска.

## Решение

Сохранить DefaultFeedLogic в качестве основной реализации и не менять
FeedLogicProvider. Доказательств существенного выигрыша производительности
от переключения на AlternativeFeedLogic не получено.

Для общего изменяемого состояния использовать синхронизацию там, где она
необходима для соблюдения инвариантов. Уровень конкурентности выбирать
по результатам измерений, а не только по количеству логических процессоров.

## Последствия и ограничения

Решение сохраняет текущую архитектуру Pawinder и не требует изменения
контракта FeedLogic. Функциональные проверки обеих реализаций пройдены.

Измерения выполнены в отдельном JVM-эксперименте на Windows 11 с Java 25.
Они не являются полноценным измерением производительности Android-приложения
на физическом устройстве. Результаты небольшого микробенчмарка FeedLogic
чувствительны к условиям запуска и сами по себе не обосновывают замену
реализации.
